This is how the backend will work:

- There will be a socket server with connections to each client
- Authentication is done in a single http exchange with Flask-Login before the client opens the socket connection
- The current hand, as well as inter-hand data will be stored in redis. The current hand will be stored as a .act-parsable string in redis
- Redis message queue will mediate between socketio and a celery app
- The celery worker will perform tasks that do the game logic, update the game state in redis, and emit events back to the clients

Other stuff:
    - Any db calls should be written in mplib, not here
    - The game container will be initialized with its table_id. Assumed to be an env var right now
        - It can deduce everything else it needs from making db calls (through mplib)
